# Plan.md — Ruri (流離) / World Chord → DTM

> 「流離(さすらい)」= 世界を漂う和音。識別子 `ruri`、瑠璃の藍は accent `#00C4CC` と符合。

> 全調律系の和音を統一表現し、DTMへ出力する製品。GitHub公開前提(MIT想定)。

---

## 目的

世界中の楽器の和音を「ルートからのセント値」で統一表現し、12平均律のみならず非12平均律(マカーム/ラーガ/ガムラン等)もDTMへ出力可能にする。12-TET先行、微分音は初期から出力経路を確保。

## データモデル(5層 + cents/ratio統一)

| 層 | 内容 | 単位 |
|----|------|------|
| 調律系 | 音高集合 + メタ: `reference_hz` / `octave_ratio`(2/1非固定=伸張・非オクターブ反復) / `source`(実測 or 理論) / `region/ensemble` | cents **または** 比 |
| 旋法/スケール/ジンス | 調律系上の音度集合 + 遷移文法(任意) | scale degree |
| 和音抽象 | ルートからの音程集合(イディオム非依存=三度堆積を前提しない) + 記述子(音程級ベクトル) | cents/比 |
| 音色/スペクトル | 楽器の部分音集合(harmonic / piano-like / bell / 実測)。**協和判定と合成の単一真実源** | 周波数·振幅 |
| 運指 | 楽器別実体化(フレット/鍵/柱), 任意 | 楽器固有 |

交換単位 = cents(純正律は比を一次保持し cents は導出)。全出力アダプタはここから生成。

**根拠(arxiv裏取り)**
- cents内部表現は妥当(music21 `Microtone(cents)` と一致)。但し純正律/倍音調律(例: 1/4音≈11/8)は比で定義、cents化で精度劣化 → 比を第一級保持
- 調律に単一正規形なし: ガムランは合奏/村ごと・オクターブ伸張・非整数倍音、マカームは地域/流派で実測が割れる → `reference_hz`/`octave_ratio`/`source` 必須化
- **協和は timbre 依存(Sethares)**: 部分音の整合で決まり、小整数比に限らない。ガムラン実測スペクトルは実調律で粗さ最小、12-TET化で粗さ増。Thai 7-TET は ranat の部分音と整合 → スペクトル層を一級化し、**Plomp-Levelt/Sethares 粗さscorer** を協和判定に採用(西洋協和規則を非西洋に当てない)。スペクトルは合成音色と共用
- 和音は**イディオム非依存表現**(三度堆積前提を排除、音程級ベクトル記述子)。理論上の協和 ≠ 演奏可能 → 運指で実体化フィルタ

## 協和・演奏可能性(評価層)

- **生成(イディオム非依存)**: 和音表をやめ、**MOS(生成音程+周期+音数)** と **最大均等集合**(Clough-Douthett)でスケール/和音を構成。非オクターブ周期・任意EDOに対応。和音=その部分集合をscorerで採点
- **協和scorer = 合成指標**: 粗さ(Plomp-Levelt/Sethares ✅実装済) **+ harmonicity/periodicity**(Stolzenburg式=比の有理近似・周期性)。粗さ単独は予測不十分(Harrison-Pearce/Eerola 62%→73%)。両成分を別々に提示
- **acoustic-only と明示**: 協和は粗さ+harmonicity+**familiarity(文化)**の合成。familiarity は音響モデル化不能 → scorerは音響記述子であって美的判定ではない。非西洋調律が音響的に粗くても文化的に協和でありうる。「良/悪」を出さない
- **運指 = 重み付きグラフ + 最短経路(A*)**: ノード=各音の実現位置(弦×フレット / 鍵×指)、辺重み=生体力学コスト(指移動距離・手幅ストレッチ・高フレット罰則・運指変更)。和音は同時押下可能性を制約に。**調弦/カポ/フレット数を入力パラメタ化**(微分音フレット・非標準調弦に対応、12-TET前提を持たない)。ML不要・決定的(再現性)
  - **個人差を一級パラメタ化**: 手幅・最大ストレッチ・運指方針はプレイヤ依存 → コスト重みを `HandProfile` で外出し(唯一の正解運指は無い)
  - **複数解の提示**: 最短一意でなく K-best(別ポジション)を返す(教育・編曲用途)
  - スコープ: 静的運指(押さえられるか + 最小コスト)に限定。動作生成(物理シミュレーション/RL)は対象外(I3)
- (experimental) **スペクトルから低粗さスケール導出**(Sethares 適応調律)= 「調律提案」機能の素地

## 出力(初期から微分音対応, 標準裏取り)

| 形式 | 役割 | 微分音 | 備考 |
|------|------|:--:|------|
| `.mid`(SMF, 12-TET) | DTM王道 | — | 自前SMFエンコーダ(zero-dep I3) |
| MusicXML | 記譜用のみ | △ | `<alter>`小数でcents可。但しMuseScore等が1/4音へ丸め/未実装 → 真実源にしない |
| Scala `.scl` + `.kbm` | 調律交換(一次) | ◎ | 最広範対応の事実上標準, フォーマット自由実装 |
| `.tun`(AnaMark) | 調律交換(二次) | ◎ | 多数シンセ対応 |
| SMF + MTS SysEx | 自己完結微分音MIDI | ◎ | ノート整数のまま調律をファイル同梱 |
| MPE | リアルタイム/和音 | ◎ | 1ノート1ch=同時最大~15音、規模制限 |
| MTS-ESP | プラグイン横断リアルタイム | ◎ | ODDSound MTS-ESP Mini(無償)が .scl/.kbm/.tun 読込 |
| WAV(Web Audio/加算合成) | 試聴・オーディオ書出 | ◎ | 非整数倍音文化は音色近似を明示 |

再生検証ターゲット = **Surge XT**(無償OSS, 調律実装の事実上標準)。微分音の真実源は **Scala/MTS**(記譜MusicXMLではない)。

## 技術選定

- フロント: TypeScript / 依存最小
- Tauri core: Rust(ネイティブ書出のみ)
- 音: Web Audio API。撥弦(ギター/箏)=拡張Karplus-Strong、金属体鳴(ガムラン/ベル)=実測部分音からの加算/モーダル合成。微分音は`detune`(cents)。合成スペクトル=協和scorerと共用(単一真実源)
- MIDI: 自前SMFエンコーダ(zero-dep)
- テスト: vitest, cents変換は性質テスト
