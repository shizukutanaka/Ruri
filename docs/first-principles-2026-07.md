# First Principles による過不足の洗い出し(2026-07)

機能を「あると良さそうか」で足し引きするのをやめ、**このプロダクトの存在目的**まで
分解して、そこから必要条件を再導出した記録。

---

## 1. 目的(第一原理)

README の定義:

> **World tuning / scale / chord backbone for DTM output**
> (世界の調律を扱い、DTM/DAW に出力するための基盤)

## 2. 目的を果たすための必要条件と、現状の充足

| #   | 必要条件                                                         | 現状                                          |
| --- | ---------------------------------------------------------------- | --------------------------------------------- |
| 1   | 正確な音高モデル(比が一次・非オクターブ周期を一級市民として扱う) | ✅ 優秀                                       |
| 2   | **出典付きの「世界の調律データ」そのもの**                       | ❌ **わずか5件**(うち2件は名称が `*_EXAMPLE`) |
| 3   | DAW 実務フォーマットへの出力                                     | ✅ 網羅(.scl/.kbm/.tun/MTS/UMP/SMF/MPE/WAV)   |
| 4   | 生成・解析(MOS/well-formed/最大均等/協和)                        | ✅ 完備                                       |
| 5   | 実行可能インターフェース                                         | ✅ CLI(info/convert/gen/presets/render)       |

条件 1・3・4・5 は完成している。**欠けていたのは条件 2 — データそのもの**だった。

## 3. 実測(2026-07 時点、着手前)

```
src/ 総行数            131,296
  core/scale.ts         80,234   (61.1%)
  data/presets.ts       38,695   (29.5%)
  ─────────────────────────────
  上記2ファイル合計    118,929   (90.6%)
```

- `data/presets.ts` は **2,185個の export 関数**を持つ一方、実データは **5件**。
  → **調律1件あたり約437個の生成関数**。

### 診断: プロダクトは倒立していた

差別化の源泉(出典付き世界調律データ)が最小で、ユーザー価値を直接生まない
機械生成コードが 90.6% を占めていた。

## 4. ゲートの再検討 — 何が本当にブロックされていたのか

`docs/product-review.md` は「調律プリセット拡充(Pythagorean・歴史的調律・
Bohlen-Pierce等)」を **「CARE準拠の出典整備が前提」** として長く未着手にしていた。

しかし実装を読むと、`loadTuningPreset`(`src/data/tuning-data.ts`)の CARE ゲートは:

```ts
if (p.source === 'measured' && !p.culturalContext && !p.region) throw …
```

**`source: 'measured'` の時のみ**発火する。CARE/OCAP は**先住民データ主権**の枠組みであり、
公刊された17〜18世紀の欧州音律理論(Werckmeister 1691、Kirnberger 1779 等)や
数学的構成物(Pythagorean、Bohlen-Pierce)には適用されない。これらは
`source: 'theoretical'` であり、必要なのは出典・ライセンス・「一例に過ぎない」注記だけ。

→ **歴史的・理論的調律は誤って過剰にブロックされていた。** 民族実測データ
(gamelan/maqam/raga)の人的ゲートは正当かつ維持すべきだが、それを理論的調律にまで
拡大適用していたことが、最大の欠落を放置した原因だった。

## 5. 実施した改善

### 5-1. 歴史的・理論的調律プリセット5件を追加(カタログ 5 → 10、倍増)

各プリセットは**独立した検証オラクル**を持つ(公刊値が黙って壊れないように):

| id                       | 内容                               | 検証オラクル                                                                               |
| ------------------------ | ---------------------------------- | ------------------------------------------------------------------------------------------ |
| `pythagorean-12`         | 純正5度の連鎖、3-limit(Eb–G# 配置) | 全度数が**厳密な比**として保存され、分子・分母が2と3のみで構成されること + 5度が厳密に 3/2 |
| `meantone-quarter-comma` | 中全音律(Aron 1523)、純正長3度     | **既存 `meantoneQuarterComma()` の構成と一致**                                             |
| `werckmeister-iii`       | Werckmeister 1691                  | C-E = 390.225c(純正386.31と12-TET 400の**間**にあること)                                   |
| `kirnberger-iii`         | Kirnberger 1779                    | **C-E が純正 5/4**(この音律の定義的特徴)                                                   |
| `bohlen-pierce-13`       | 3/1(tritave)の13等分、非オクターブ | **`edo(13, 440, 1200·log₂3)` と一致**                                                      |

Pythagorean は cents ではなく**比のまま**保存し、ライブラリの「比が一次」設計を
データ側でも体現している(`.scl` 出力で精度が落ちない)。

### 5-2. `ruri presets` コマンド — curated データを CLI から到達可能に

追加前、CLI から curated プリセットに**一切アクセスできなかった**(`gen` は理論生成のみ)。

```
ruri presets                              # 全10件を id・度数・種別・出典付きで一覧
ruri presets kirnberger-iii -o k3.scl     # 任意の出力形式で書き出し
```

一覧は各調律の **citation を必ず併記**する。数値を出典から切り離さないという
データモデルの原則を、CLI 表示層でも保つため。

### 5-3. `--name` オプション

`convert`/`gen`/`presets` の出力調律名を上書き。共有する `.scl`/`.tun` に
意味のある名前を付けられる。

## 6. 過剰(scale.ts)への対応方針

90.6% の機械生成コードは**本計画では削除しない**。理由:

- 公開 API からは既にバレル(`src/core/index.ts`)で隠蔽済み → **API 汚染は発生していない**
- 大量削除は高リスク・低リターン(ユーザー価値を直接増やさない)

代わりに **数値を記録し、「これ以上増やさない」ルールを明文化**した
(`docs/model-handbook.md` §5)。削除に着手する場合は、独立にスコープを切った作業とする。

## 7. 結果

- 調律カタログ: **5 → 10 件**(理論的調律が 2 → 7 件)
- CLI: curated データへ到達可能に(`presets`)
- テスト: 7,308 → **7,322 件緑**(+14、うち7件は新プリセットのオラクル検証)
- 依然として人的ゲート下にあるもの: 民族実測調律の拡充(DaMuSc 等)、
  vitest 3→4、カバレッジ方針 — いずれも `docs/model-handbook.md` §6 に記載。

本書 §6 は「`scale.ts` の大量削除は本計画ではスコープ外」としていた。その後の
マスク式アルゴリズム適用(「10%を戻さないなら削り足りない」)で**実行済み**:

| --------------------- | ------------------------ | ----------------------------------------------- |
| 公開API(明示export名) | 1,445                    | **328**                                         |
| `scale.ts`            | 80,234行 / 3,711宣言     | **4,759行 / 440宣言**                           |
| `presets.ts`          | 38,695行 / 2,206宣言     | **702行 / 32宣言**                              |
| 生成テスト            | 99,237行 / 12,311ケース  | **0**(全パスから除外され一度も走っていなかった) |
| `src/` 合計           | ~285,000行               | **50,339行**                                    |
| カバレッジゲート      | 80%要求 / 実測36% / 無視 | **carve-outなしで97.06%通過**                   |

到達可能性は curated barrel + CLI + 手書きアダプタからの**推移閉包**で機械的に判定。

367 export・CLI 出力・12プリセットすべて同一であることを確認済み。
