## 技術的実現性(検証済 = ゴール到達可能)

- **微分音再生は確実に可能**: detune は cents 単位ネイティブ(1200=オクターブ)、a-rate AudioParam、2015年以降全ブラウザ対応。設計通り鳴る。
- 単一HTML/Web Audio で微分音ポリフォニーは実現可。ただしオシレータ数 = 和音音数 × 部分音数 で増えるため、**部分音数の上限とvoice poolが必要**(性能ゲート、WORKFLOW §5のバンドル/性能予算に追加)。
- → アーキ前提(単一HTML起動→Tauri昇格)は妥当。

## 新たに判明したゴール制約(法的安定性)

- **EAA(欧州アクセシビリティ法)2025-06-28 施行**: EUで提供する製品はWCAG 2.1 AA必須。無料公開でも公開先がEUを含むなら対象になりうる。
- → A11y を「あったら良い」でなく**ゴール要件**へ格上げ。POUR原則(知覚可能/操作可能/理解可能/堅牢)。
- 既にCLAUDE.md §7 にWCAG AA記載あり → 設計段階から組込み(後付けは高コスト)。具体: 全インタラクティブ要素キーボード操作 + focus-visible、aria-label、コントラスト4.5:1、フラッシュ無し。
- **音アプリ特有**: 音高/協和を**色だけに依存させない**(数値cents・テキストも併記)。スクリーンリーダで運指・協和値を読み上げ可能に。

## リスク(ゴール阻害要因)

- **データの文化的正確性**: 誤った調律値は信頼を壊す。measured値は出典必須、唯一正解と称さない(脱植民地)。人間ゲート(文化的妥当性, I1)。
- **スコープ膨張**: 採譜/楽曲生成へ流れる誘惑(競合領域)。OUT明記済、堅持(I3)。
- **UI肥大でオフライン哲学崩壊**: バンドル予算をCIゲート化(既定済)。データは遅延ロード検討。
- **性能**: 部分音×和音のオシレータ爆発 → voice上限。

## 結論

ゴール到達は**技術的に実現可能**(微分音再生・運指・協和すべて検証済、コア8割完成)。
残るは**製品外殻**(データ→UI→配布)であり、新規研究は不要、実装フェーズ。
次の一手 = **優先順位1: 世界の調律データ + ローダ + provenance検証**(差別化の核を埋める)。
